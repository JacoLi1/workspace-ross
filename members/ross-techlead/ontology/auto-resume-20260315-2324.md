## 🛠️ Refactoring Plan (What Would Be Done If Code Existed)

Assuming we had a monolithic `SimulationEngine.java` (5000+ LOC), the extraction would:

### Dependencies to Remove from Core:
- **Physics references** (`BulletPhysics`, `CollisionWorld`)
- **Device system imports** (`DeviceManager`, `Stove`, `Oven`)
- **Action/Recipe parsers** (`RecipeExecutor`, `ActionQueue`)
- **Ontology query layer** (`OntologyQueryService`)
- **Persistence/IO** (`StateSerializer`, `ResourceLoader`)

These would be moved to upper layers or made optional via interfaces.

### New Abstraction Layers Added:
1. **`TimeStep` immutable value object**  
   Encapsulates `deltaNanos`, `simulationTime`, `realTimeOffset`. No external dependencies.

2. **`Scheduler` interface** (abstraction)  
   Methods: `schedule(Event)`, `tick(TimeStep)`, `pendingEvents()`. Implementation: `FixedStepScheduler`.  
   Allows swapping deterministic vs real-time schedulers without affecting consumers.

3. **`Event` sealed hierarchy** (abstraction)  
   Base class/interface for all events. Concrete types: `DeviceEvent`, `PhysicsEvent`, `AgentAction`, `SystemEvent`.  
   Core only defines `SystemEvent` (time sync, GC hints). Others defined in their owning modules.

4. **`SimulationListener` callback interface**  
   Modules subscribe to tick events, state changes. Decouples Core from concrete consumers.

**Result**: Core becomes a standalone `core.jar` with **zero outgoing dependencies** (only JDK).
